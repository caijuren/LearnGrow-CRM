## Issue #3: 用户数据删除接口
**优先级:** 🔴 P0  
**预估工时:** 2天  
**指派给:** @caijuren

### 任务描述
实现符合GDPR/个保法要求的用户数据删除功能，支持级联删除和软删除两种模式。

### API设计
```typescript
// DELETE /api/wx-users/:id
// Request Body:
{
  hard_delete?: boolean  // 默认false(软删除)，true为物理删除
}

// Response:
{
  success: true,
  deleted_user_id: number,
  cascade_deleted: {
    children: number,
    checkin_records: number,
    orders: number,
    follow_ups: number,
    points_ledger: number
  }
}
```

### 数据库变更
```sql
-- wx_users表增加deleted_at字段
ALTER TABLE wx_users ADD COLUMN deleted_at DATETIME;

-- 其他关联表同样增加deleted_at
ALTER TABLE children ADD COLUMN deleted_at DATETIME;
ALTER TABLE checkin_participants ADD COLUMN deleted_at DATETIME;
-- ... 其他表
```

### 业务逻辑
1. **软删除(默认)**
   - 标记`deleted_at`时间戳
   - 查询时自动过滤 `WHERE deleted_at IS NULL`
   - 用户在前端不可见，但数据仍保留(审计需要)
   
2. **硬删除(需admin权限)**
   - 物理删除所有关联数据
   - 记录操作日志到`audit_logs`表
   - 需二次确认防止误删

3. **级联删除顺序**
   ```
   1. points_ledger (积分流水)
   2. checkin_records (打卡记录)
   3. checkin_participants (活动参与)
   4. orders (订单)
   5. follow_ups (跟进记录)
   6. children (孩子档案)
   7. wx_users (用户本身)
   ```

### 代码实现要点
```typescript
// api/services/user-delete.service.ts
export async function deleteUser(userId: number, hardDelete = false) {
  const db = getDb();
  
  if (!hardDelete) {
    // 软删除
    db.prepare(`
      UPDATE wx_users SET deleted_at = datetime('now') WHERE id = ?
    `).run(userId);
    
    // 同样软删除关联数据...
    return { success: true, cascade_deleted: {...} };
  }
  
  // 硬删除(事务保护)
  db.transaction(() => {
    db.prepare('DELETE FROM points_ledger WHERE wx_user_id = ?').run(userId);
    db.prepare('DELETE FROM checkin_records WHERE participant_id IN (...)').run(...);
    // ... 按顺序删除
    db.prepare('DELETE FROM wx_users WHERE id = ?').run(userId);
  })();
  
  // 记录审计日志
  db.prepare(`
    INSERT INTO audit_logs (action, user_id, created_at) 
    VALUES ('USER_DELETED', ?, datetime('now'))
  `).run(userId);
}
```

### 管理端UI

## Issue #4: 备份加密实现
**优先级:** 🟡 P1  
**预估工时:** 1天  
**指派给:** @caijuren

### 任务描述
当前备份zip包明文存储，存在数据泄露风险，需增加AES256加密。

### 技术方案
使用Node.js内置`crypto`模块进行流式加密，避免大文件内存溢出。

### 代码实现
```typescript
// scripts/backup.ts (修改)
import crypto from 'crypto';
import fs from 'fs';
import archiver from 'archiver';

function encryptBackup(inputPath: string, outputPath: string, key: string) {
  const password = key.slice(0, 32); // 取前32字节作为密码
  const iv = crypto.randomBytes(16);
  
  const cipher = crypto.createCipheriv('aes-256-cbc', 
    Buffer.from(password), 
    iv
  );
  
  const input = fs.createReadStream(inputPath);
  const output = fs.createWriteStream(outputPath);
  
  // 先写入IV(用于解密)
  output.write(iv);
  
  input.pipe(cipher).pipe(output);
}

// 备份流程修改
async function createEncryptedBackup() {
  const zipPath = `/tmp/backup-${Date.now()}.zip`;
  const encryptedPath = `${zipPath}.enc`;
  
  // 1. 创建zip
  await createBackup(zipPath);
  
  // 2. 加密
  const encryptionKey = process.env.BACKUP_ENCRYPTION_KEY;
  if (!encryptionKey) {
    throw new Error('BACKUP_ENCRYPTION_KEY not set');
  }
  await encryptBackup(zipPath, encryptedPath, encryptionKey);
  
  // 3. 删除明文zip
  fs.unlinkSync(zipPath);
  
  return encryptedPath;
}
```

### 解密恢复
```typescript
// scripts/restore-backup.ts (修改)
function decryptBackup(inputPath: string, outputPath: string, key: string) {
  const password = key.slice(0, 32);
  
  const input = fs.readFileSync(inputPath);
  const iv = input.slice(0, 16); // 读取前16字节IV
  const encryptedData = input.slice(16);
  
  const decipher = crypto.createDecipheriv('aes-256-cbc', 
    Buffer.from(password), 
    iv
  );
  
  const decrypted = Buffer.concat([
    decipher.update(encryptedData),
    decipher.final()
  ]);
  
  fs.writeFileSync(outputPath, decrypted);
}
```

### 环境变量
```bash
# .env.production
BACKUP_ENCRYPTION_KEY=your_64_char_random_string_here
```

### 验收标准
- ✅ 备份生成的`.enc`文件无法直接解压
- ✅ 使用正确密钥能成功解密并恢复
- ✅ 错误密钥解密失败(抛出异常)
- ✅ 加密后备份体积增加<1%

### 测试
```bash

# 尝试直接解压(应失败)

```
