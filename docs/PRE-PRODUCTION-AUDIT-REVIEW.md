## 四、JWT和认证安全重新评估

### JWT_SECRET生产环境强制配置 ✅

**验证结果**：
- `api/services/auth.ts` L7-10: 生产环境会检查JWT_SECRET长度和有效性
- `scripts/preflight-prod.ts`: 预检脚本会在启动前验证
- 如果未配置或使用默认值，应用**无法启动**

**结论**: **低风险** - 有完善的强制校验机制

### Token无法撤销 🔴

**验证结果**：
- 前端logout仅删除localStorage中的token
- 后端**无任何token黑名单或撤销机制**
- Token在7天有效期内始终有效

**风险评估**：
- 如果token泄露，攻击者可在整个有效期内冒用身份
- 无法主动撤销会话（如密码修改后）

**结论**: **P1** - 高优先级安全问题，建议缩短token有效期至1天，或在用户表增加`last_valid_token_time`字段

### 后端信任JWT中的role字段 🔴

**验证结果**：
- `auth.ts` L47-53: `adminOnly` 直接检查 `request.user.role !== 'admin'`
- `request.user` 来自JWT payload，**未与数据库同步验证**
- 如果JWT_SECRET泄露，攻击者可伪造任意角色token

**结论**: **P1** - 敏感操作（如用户删除、备份下载）应二次验证数据库中的角色

## 五、CORS风险重新评估

### 理论风险 vs 实际风险

**配置现状**：
```typescript
await app.register(cors, { origin: true, credentials: true });
```

**理论风险**：
- `origin: true` 允许所有来源
- `credentials: true` 允许携带凭证
- 违反CORS规范（credentials=true时origin不能为*）

**实际可利用性**：
- ✅ Token存储在localStorage，非Cookie
- ✅ 使用Authorization header传递token
- ✅ CSRF攻击无法利用（浏览器不会自动携带localStorage内容）
- ⚠️ 需要XSS漏洞作为前置条件才能窃取token

**三个结论**：
1. **理论风险**: P1 - 配置不规范，存在潜在安全隐患
2. **实际风险**: P2 - 在当前技术栈下难以被直接利用
3. **是否阻断上线**: **否** - 建议白名单化origin，但不阻断上线

**建议修复**（预计30分钟）：
```typescript
await app.register(cors, { 
  origin: ['https://learngrow.com', 'https://www.learngrow.com'], 
  credentials: true 
});
```

### 发现的越权风险

#### 1. 管理端API缺少所有权验证 ⚠️

**示例**：
```typescript
// /api/wx-users/:id
router.get('/:id', async (request: any, reply: any) => {
  const id = parseInt(request.params.id);
```

- 但这是CRM系统的**设计决策**（管理员需要查看所有客户数据）
- **不是安全漏洞**，而是业务需求

**结论**: **不构成P0/P1**，属于正常的管理端权限模型

根据**真实风险**和**修复成本**综合评估，以下是必须优先修复的5个问题：

- **修复成本**: 2小时
